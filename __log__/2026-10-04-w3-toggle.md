What changed and why, per card (TDD from the verbatim scenario cards; one commit each):

- **todos/05** — `todos.Change(id, ChangeFields{Title, Done})` lands in
  `todos/change.go`: a column-wise UPDATE touching only the supplied fields,
  so a done-only change never rewrites the title (and the title direction,
  W4's card, is already expressible in the shape without rework). The updated
  row is read back and returned after the write commits. Foundation for the
  edit wave's use of the same operation.
- **todos/08** — the affected-row count of the UPDATE distinguishes
  not-found (the store workplan's data-flow note): zero matched rows means
  nothing was written and the result is the typed `ErrNotFound`. Typed
  outcome errors carry no HTTP semantics — mapping stays in api.
- **todos/09** — a Change supplying neither title nor done is rejected before
  any lookup (`ErrNoFields`); the card test pins that the list is byte-equal
  across the rejection.
- **api/06** — `api/change.go` (own file for sibling-lane conflict
  discipline): `PATCH /todos/{id}` parses the id and an optional-fields body
  (pointers distinguish absent from present-with-zero), calls the store's
  Change through the port, answers 200 with the updated todo JSON. The port
  and route registration in `api/handler.go` gained one-line appends each;
  `cmd/todo/main.go` gained one mount line so `/todos/{id}` reaches the api
  handler on the composed server (the exact `/todos` mount cannot match it).
- **api/08** — not-found maps to 404 `{"error": "no such todo"}` — the
  mapping the api workplan fixes, driven by its card's red step.
- **api/09** — defensive path: a body that is an empty JSON object — or no
  body at all — arrives as "no fields supplied" and lands on the store's
  `ErrNoFields`, mapped to 422 stating that at least one field is required;
  malformed JSON stays 400, the workplan's transport/rule distinction.
- **ui/08** — the row checkbox PATCHes `/ui/todos/{id}` via htmx
  (`ui/toggle.go`, new file): hx-vals carries the done value **opposite of
  the row's rendered state**, so both checkbox directions send an explicit
  `done` without a live-DOM js expression; the endpoint performs the change
  through the api contract over real HTTP (never in-process) and returns the
  rendered list as an outerHTML swap fragment targeting `#todo-list` —
  reusing W1's list template verbatim, so done styling and the
  no-edit-control-on-done-rows rule hold across swaps with zero duplication.
  The shared-file hunks are one route line (`ui/handler.go`) and the checkbox
  line in `ui/render.go`.
