What changed and why, per card (TDD from the verbatim scenario cards; one commit each):

- **todos/02** — `Create` now enforces the stated text rules before any write:
  trim → non-empty (else the `ErrTitleRequired` invalid-text outcome) → at most
  `MaxTitleLength` = 500 runes of the trimmed text (else `ErrTitleTooLong`, the
  other invalid-text kind). The store persists the trimmed title. Both outcomes
  are plain typed errors with no HTTP semantics; rejection writes nothing.
  500 is the stated limit from the workplan data-model table, now a named
  constant so the api states it without restating the number.
- **api/01** — `POST /todos` (new `api/create.go`, registered with one line):
  parse `{ "title": ... }`, call the store port (extended with `Create`), map
  success to 201 + created-todo JSON, malformed JSON to 400
  `{"error":"invalid request"}` per the contract. Tested against the real
  SQLite store so persistence is proven, not asserted by a fake.
- **api/02** — the create handler maps `todos.ErrTitleRequired` to 422
  `{"error":"title is required"}` (covers empty, whitespace-only, and missing
  title — the store owns the rule, the handler only translates it).
- **api/03** — `todos.ErrTitleTooLong` maps to 422 stating the limit, the
  message composed from `todos.MaxTitleLength` so the number has one owner.
- **ui/05** — the page's create form posts via htmx (`hx-post="/ui/todos"`,
  target `#todos-area`): the fragment handler calls the api contract over
  HTTP, then answers the fresh list state plus an out-of-band reset of
  `#create-area`, so the new row appears last (not-done) with no navigation
  and the input/button are ready for the next todo.
- **ui/06** — on api 422 the fragment endpoint answers 422 with a create-area
  fragment: the api's stated reason rendered visibly (`#create-error`) and the
  typed text kept in the input; a three-line htmx `responseError` glue swaps
  that server-rendered fragment into place (htmx does not swap 4xx bodies on
  its own).
- **ui/07** — same surface carries the api's limit message verbatim, so the
  500-character limit is stated without the ui owning the number.
- **wave end** — `e2e/w2-create.js` re-executes the parent scenarios in
  chromium (create appends without reload — navigation-marker asserted, blank
  submit states the reason, over-limit states the limit, reload shows
  persistence), wired behind `make e2e-w2`; `archspec verify --strict` stays
  at four modules.
