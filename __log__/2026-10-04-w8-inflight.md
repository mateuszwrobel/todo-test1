Card ui/16: while an operation triggered from a control is in flight, that control is disabled until the response arrives, and a second activation of the same control causes no request. Parent scenario "Repeat activation while an operation is in flight" adds the observable form: the list ends in the state produced by exactly one operation. Server-side behavior was already honest (W6 made every failure stated); this card is purely the client-side repeat-activation gate — no server change, the decision record already anticipated it ("Controls for an operation stay disabled from request until response"; duplicate suppression on the server was explicitly rejected).

**Blocking choice — htmx-native `hx-disabled-elt`, nothing custom.** htmx 2.0.6 disables the named elements synchronously when the request starts and re-enables them on every completion path (load, error, timeout, abort), so the failure path cannot leave a control dead by construction — no `htmx:afterRequest` glue, no JS of our own. Placement detail that decides correctness: htmx resolves `hx-disabled-elt` from the request *origin* element, so on the two form-submitted controls (create, edit-save) the attribute lives on the form and names the submit button — the button is what the user activates, and a disabled submit button also closes the Enter-key implicit-submission path (a disabled button is no longer the form's default button). The checkbox and delete button are their own request origins and take `hx-disabled-elt="this"`. The edit form's selector is row-scoped (`#todo-{id} .save`) because every row carries a `.save` — a bare class selector would block saves on other rows, which the card does not ask for.

**Per-control scope reading of the card.** "That control is disabled" is the whole mandate: the card disables exactly the control in flight, and no scenario states any other control being unusable. The e2e pins this reading both ways — during a toggle's in-flight window the other row's checkbox and delete are asserted *not* disabled, while the activating checkbox is asserted disabled. No page-wide or row-wide blocking was added.

What changed and why:

- **ui/render.go** — the checkbox and the row delete button gained `hx-disabled-elt="this"`; the edit form gained `hx-disabled-elt="#todo-{id} .save"` and its Save button the `.save` class it names. The W6 region-swap wiring (`#todos-area`, innerHTML) is untouched: swapped-in rows re-render with the same wiring, and a swapped-in control arrives enabled.
- **ui/create.go** — the create form gained `hx-disabled-elt="#create-form button[type=submit]"`. The success OOB re-render and the failure re-render of the create area both carry the attribute, so the gate survives every re-render path.
- **ui/inflight_test.go (new)** — unit pins for all four controls' disable wiring on the rendered page (self-disable for checkbox/delete, exact-button selectors for the two forms, and the `.save` class the row-scoped selector depends on).
- **e2e/w8-inflight.js + `make e2e-w8`** — the in-flight window is proven with a Playwright `page.route` proxy on the ui endpoints: every control request is counted at the proxy, then held ~400ms *before* `route.continue()`, which keeps the browser-side XHR pending — that pending window is where the test observes the disabled state, force-clicks the disabled control (a trusted click on a disabled form control fires no event, so the assertion measures real browser suppression, not a JS filter), and reads the proxy counter. Exactly one routed request per double activation plus the `GET /todos` store truth proves "no additional effect beyond the single operation" for all four controls (one toggle → done once; one create → the title exists exactly once; one edit → the old title is gone, the new appears once; one delete → exactly one row absent). The failure path forces a 500 on a toggle PATCH: the double activation still sends one request, the store shows no effect from the failed call, the checkbox re-enables (htmx's completion-path re-enable), and an immediate retry lands — the control provably never stays dead.
- **Makefile / README** — `e2e-w8` target; W8 paragraph appended to the product section.
