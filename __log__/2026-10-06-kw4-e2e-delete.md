# KW4 e2e — delete lane

Wave-end integration for KW4: re-executed parent scenarios "Delete card" +
the missing-card leg of "Operation on missing card" for DELETE in the browser
(workplans/dependencies_kanban.md §KW4).

What changed and why:
- `e2e/kw4-delete.js` — new lane file (kw1–kw3 lanes untouched), same harness
  shape as kw3: fresh seeded temp board + port + server per scenario, SIGTERM
  teardown, window-marker no-reload proof, out-of-band `sqlite3` DELETE for
  the stale-page Given. Scenario 1 pins the parent scenario whole-board:
  deleting a middle To Do card drops it without a reload, the column packs
  with DOM order card-for-card equal to GET /board order under contiguous
  0..n-1 positions (the contract's "no gap"), other cards untouched; the
  Done-card leg confirms a done card is as deletable as any other and Done
  then states its emptiness; reload agrees with the contract. Scenario 2 is
  the DELETE leg of the missing-card scenario: out-of-band file delete keeps
  the page stale, the click states "no such card" over the re-rendered truth
  (banner + board IS GET /board — nothing faked), and the statement dies at
  reload. Scenario 3 pins that deleting a column's last card reaches card
  ui/02's stated empty treatment through deletion while other columns keep
  their cards. The out-of-band staging stays necessary even though DELETE
  exists now: staging through the endpoint would re-render the page truth
  first and destroy the stale state the Given requires.
- `Makefile` — KW4 lane line in the `e2e` target + header comment.
- `e2e/README.md` — KW4 section describing the lane.

Product bugs observed: none — every assertion held against the composed
server on first behavioral pass (only the lane's own assert shapes needed
fixing: a rows-vs-cards field mismatch, and the seeder's placement indexes
are 0-based, not 1-based as kw3's five-title example reads).

Verification: `make e2e` fully green (kw1+kw2+kw3+kw4), `go test ./...` green.
