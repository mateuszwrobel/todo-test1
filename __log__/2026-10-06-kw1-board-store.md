New `board` package lands per ADR-003 pivot and the board-store workplan: the Open/Create/List slice of the store contract, one commit per scenario card (board/01, board/02, board/05). SQLite conventions mirrored from the superseded `todos` store — same `modernc.org/sqlite` driver, single pooled connection, create-if-not-exists schema on open, same error-wrapping and test style; `todos` itself untouched and green throughout.

Schema is the workplan Database section: `cards` with autoincrement id (never reused), title CHECK (non-blank, ≤500 chars), column CHECK over the three-value enum, position ≥0, and the (column, position) index for the ordered read. The title CHECK is deliberately the minimal storage-level guard only — blank/over-long rejection as stated *behavior* (error outcomes callers can name) is KW2's board/03+04 and was not built here. Create appends at position = current todo count inside one transaction, so the contiguity invariant and the all-or-nothing risk mitigation hold from the first mutation. List always answers the three fixed columns in order todo, in_progress, done, cards by position; grouping into that shape is the module's job, not callers'.

Tests derive from the cards' Gherkin as tables over the general contract — the "two cards / Buy milk / position 2" scenario is one row, not a special case. board/05 fixtures seed the todo column through Create (the ledger's "List seeds via Create") and place in_progress/done fixtures by direct insert through the same schema, since the contract operation that relocates cards there (Move, board/06) only lands in KW5; one test pins position-order reads against insertion/identifier order.

`architecture.spec.toml` declares the `board` module (matches `*/board`, no internal deps, forbidden against api/ui/server) and adds it to no_cycles. The future api→board and server→board edges are *not* pre-declared: `archspec verify --strict` treats declared `depend_on` entries as required edges ("missing edge" when absent), so each edge gets declared at the wave that first imports board (api/01, server/01). Verified: `go build ./... && go vet ./... && go test ./board/ ./todos/` green, `archspec verify --strict` green (5 modules, 1 constraint).
