The Move operation of the board store contract lands, one commit per card (06 → 07). Shape decision up front: the KW3 note in Change's doc comment scheduled "insert at an index, same-column reorder" as the dedicated KW5 refinement. Two shapes were on the table — extend Change with a `position *int` direction, or add a standalone `Move(id, column, position)`. Move it is: Change's shipped signature is the api PATCH mapping (api/change.go calls it with title/column directions only), and the task forbids touching api/, so extending the signature would break a caller the lane may not edit. Move also reads cleaner at the contract: a move *always* carries a target index — there is no position-absent move to represent — while Change keeps its shipped column-direction meaning (bottom append) for the HTTP verb that only knows directions.

Shape and semantics:

- **`Move(id int64, column Column, position int) (Card, error)`** — placement = target column, target index. `position` indexes the target column's cards *after* the moved card is removed from it, which is exactly what the two cards compose to: board/06 inserts B at index 1 of [X, Y] → [X, B, Y]; board/07 removes A from [A, B, C] then inserts at 2 → [B, C, A]. One list-based path serves both: read the target's order excluding the card, clamp the index, splice the card in, write positions 0..n in the spliced order — uninvolved cards keep relative order by construction (the "keeps neighbors" clause). Cross-column additionally flips the card's column and renormalizes the source, so the source gap closes through the existing helper — same mechanics done-in and done-out.
- **Out-of-range position clamps** — the cards are silent on it, so the index clamps into the valid insertion range ([0, remaining length]): negative → top, past-end → bottom. Chosen over a typed error because the cards' own end positions (index 0, index == size) are already the clamp results, and a total function gives the drag layer one outcome to reason about. The clamp is documented on Move and pinned by tests.
- **KW3 consequences stated honestly** — Change is untouched, so its bottom-append pin (TestChangeColumnMovesToBottomAndClosesGap) survives green; the same-column no-op pin (TestChangeColumnToSameColumnPlacesNothing) keeps its assertions — column-only Change still places nothing — but its *rationale* flips: "Change never reorders within a column" was a not-yet-built disclaimer, and board/07 replaces that store-level claim. Reorder exists now, in Move; the test comment is rewritten to say so, citing board/07.

Rejections stay board-style: column enum guard before Begin (ErrInvalidColumn, zero Card, no statement), existence read as the transaction's first statement (ErrCardNotFound, zero Card, no id burned), one transaction for the whole placement. Tests land as Gherkin-derived tables in board/store_move_test.go covering the scenario rows verbatim, index 0/end/single-card targets, same-column up/down/exact-position no-op, uninvolved-card identity pins, cell-for-cell board pins on rejections, and the contiguity invariant asserted on every column after every accepted op.
