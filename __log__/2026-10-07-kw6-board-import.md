**`Import(batches []SeedBatch) error` + `SeedBatch{Column; Texts}`** — one exported operation appended to `board/store.go` beside `Seed`, its exact multi-column one-transaction sibling: the composition root's upcoming migration needs all three columns' ordered material to land as a single unit, and per-column `Seed` calls would leave intermediate boards observable between commits.

What the operation guarantees, and why it looks the way it does:

- **Placement = Seed, per column.** Each batch's texts append below that column's residents (count at arrival, then count+1…) in the list's order, so positions stay contiguous 0..n-1 and the given order is the stored order — the workplan keeps seeding an "ordered insert, not a migration policy", and Import is the same doctrine with the batch dimension added: deciding WHAT to import stays in the composition root. Batches naming the same column are handled by re-reading the count per batch inside the transaction, so batch order alone decides a column's layout — no special case needed.
- **All validation before Begin, enum-guard-all first.** Every batch's column is screened against the fixed enum across all batches *before any text is read* (Seed's "the guard answers before the texts are read" widened to the batch dimension, so a bad column wins over text faults regardless of batch order — pinned), then every entry through `validateText` at its batch and entry index; trimmed titles are kept so the transaction inserts exactly what the rule normalized. Any failure is the typed store error (`errors.Is`-mappable `ErrTextRequired`/`ErrTextTooLong`/`ErrInvalidColumn`) whose message names the failing batch and entry, with zero statements executed: board cell-for-cell unchanged, no id consumed — the probe-Create no-burn pin reused from the seed tests.
- **One transaction, one commit.** Accepted imports run count-then-inserts per batch inside a single `Begin`…`Commit`; ids come from the same autoincrement as everything else (fresh, never preserved). Empty batches list — or one whose batches hold no texts — is a nil no-op answered before `Begin`, matching Seed's nothing-read-nothing-written, while an invalid column is still refused structurally even with empty texts.
- `validateText`'s entry-point list updated to name the fourth door.

Tests (`board/store_import_test.go`, seed-test style, all helpers reused — `maxID`, `assertPlacements`, `seedBoard`, `boardEqual`, probe-Create id pins): three-column order preservation with non-creation-sequence lists and a trimmed padded text, seven rejection rows (blank/whitespace/over-long at varying batch+entry positions, invalid column in first/later batch, enum-wins-over-text, empty-texts-bad-column) each pinning the named-batch message, unchanged board, and no id burn, empty no-op on both board shapes with the first-id-is-1 pin, append-below-existing with resident cell-for-cell and fresh-id pins, and an import→Close→reopen round trip through the board/13 machinery.
