Card ui/14: a page stale about a todo that no longer exists states the failure for **any** operation — toggle, edit-save, and delete of the missing id each surface it visibly, never a silent no-op or fake success. The api-side 404s already existed from W3–W5 (`{"error":"no such todo"}`); this card is the ui surfacing across all three operations plus the reload-truthfully angle.

**Surface choice — banner, per the workplan.** The workplan's error-surface decision splits the two cases explicitly: errors attach to the triggering area (create area or row), *and for missing/stale cases* a banner-style notice. The existing per-row edit-error mechanism serves row-attached 422 refusals — the todo exists and its row carries the reason. A missing todo has no row to attach to: the todo is gone from the server, and any truth-synced re-render drops its row, so a row-scoped surface would delete its own message. The banner is therefore the one coherent failure surface for all three operations, matching mockup 06 (banner above the list). The per-row edit-error mechanism is left exactly as it was — the two surfaces are complementary, not competing, and each failure kind keeps its single owner.

What changed and why:

- **ui/stale.go (new)** — owns the surface: `bannerTmpl` (one `#missing-todo-banner`, text = the contract's stated reason, message ownership stays with the api) and `writeMissingTodo`, which answers the fragment endpoint with 404 + banner + the freshly re-read list state. The truth re-render is what makes the failure honest: the stale row disappears, a checkbox that flipped on click flips back, no row looks like the operation succeeded.
- **ui/toggle.go / ui/edit.go / ui/delete.go** — each operation's 404 branch now routes through the shared surface instead of relaying a plain `http.Error` body htmx could never swap (toggle's silent-checkbox gap was the worst case — the box stayed flipped). `patchDone` now surfaces the contract's reason like the other directions do.
- **ui/render.go** — row controls (checkbox, edit form, delete button) now target `#todos-area` with an innerHTML swap, and the page's single error router sends any failed HTML response into that same region. Consequence by construction: every swap replaces the region whole, so a stated banner can never outlive the next operation, and success/failure share one swap surface. The edit-422 row-error flow is unchanged in behavior — it just swaps through the region like everything else (the fragment still carries the reason on the row with the band open).
- **tests** — `ui/stale_test.go` covers the card per operation (404 → HTML → banner exactly once + surviving truth, banner over the empty state, no banner on success paths, and the region-target swap contract the browser depends on); three existing wiring assertions moved from `#todo-list`/outerHTML to `#todos-area`/innerHTML, which is the swap-contract change above.
- **e2e** — `e2e/w6-stale.js` + `make e2e-w6`: real chromium; each operation run against a todo deleted behind the page's back via a direct api DELETE (the second page): banner stated ("no such todo", visible, once), stale row not left faking the operation, survivors byte-equal to server truth, zero navigation, reload → truth with no banner.
