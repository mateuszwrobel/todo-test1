The one-time todo migration lands in the composition root, where the workplan places it: startup opens the board, a guard decides whether a todo source is migration material or past evidence, and a qualifying source is read read-only, partitioned by done state in creation order, and placed through **one** `board.Store.Import` call — one transaction, the store's own primitive from board/14. **What changed and why.**

- **`cmd/todo/migration.go` — `importTodos`, the whole policy.** Guard, presence check, mapping (not-done → todo top-to-bottom by creation order, done → done likewise, in_progress invented from nothing), single `Import`, loud failure. It runs after the store opens and before `net.Listen`, so a failing import never leaves a half-started server — the exit is the no-half-process evidence, the same shape card 06 already pins. The source path is a new `--todo-db` flag (default `todos.db`): the composition root owns paths, and this one dies with the flag once the migration retires after KW6.
- **The guard reads the board, not the filesystem.** The workplan's decision wording is "presence of the board schema", but that observation cannot satisfy card 05: `board.Open` creates the schema file before the import runs, so after a stop during import — crash, or a refused poisoned source — a schema-exists guard declares the board "already created", the source is skipped forever, and "the import completes on that next start if it had not landed" breaks.
