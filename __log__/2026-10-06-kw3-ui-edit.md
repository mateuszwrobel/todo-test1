What this lane changes and why.

The edit affordance goes live on every card in every column, Done included — the workplan's no-frozen-done reading of J6: a done card's text is editable because done is just a column and the edit touches neither position nor identity (the column field is deliberately absent from the request body; moving is the drag card, KW5). Pattern chosen: the inline edit band, matching mockup k6 and the design system's existing `.edit-form`/`.editing`/`.input`/`.btn` classes — the card's Edit control reveals a hidden prefilled form (client-side class toggle, zero requests) whose Save submits through htmx. The KW1 placeholder buttons stay plain elements; only the band carries wiring.

Why the create fragment pattern again: the repo's proven no-reload mechanism is a swap fragment from a ui fragment endpoint over the api contract, and the workplan's re-render-from-server decision says the content comes from server truth, never a local guess. `PATCH /ui/cards/{id}` (ui mux, mirroring `POST /ui/cards`; the composition root needed no new mount — `/` already routes to the ui handler) issues a real `PATCH {apiBase}/cards/{id}` with the contract's `{"title": ...}` body, then answers: on 200 a fresh board-area fragment (the card shows the new title at the position the server holds it — in-place by server truth, htmx swapping into `#board-area`); on 422 the board re-rendered from a fresh read with the contract's verbatim reason attached at the editing card (`error-text` under its still-original title) and the contract's status mirrored; on 404 (stale page — card deleted in another session) the contract's "no such card" in the banner class above the truth re-rendered without the card, so nothing is left faking the change. The shell's `htmx:responseError` routing gains an edit arm so every 4xx body swaps through the same engine — still no browser-side rendering. The full stale surface shared by all card operations stays with ui/11 (KW5); this is the edit arm's stated 404 path only.

Cancel discards without a request by construction: a plain `type="button"` control the shell script hides the band for, no hx-* anywhere on it. The delete affordance stays the inert placeholder until KW4. In-flight blocking posture is not claimed here (ui/12, KW6); the create form's `hx-disabled-elt` precedent intentionally not copied since ui/12 will pin blocking for every control at once.

CSS gain is one rule: `.card.editing .card__title` hides the title while the band is open (mockup k6's title-for-input swap); the generic band display rules already covered `li.editing`. ui still imports zero project packages (the new coupling is HTTP-only), so archspec edges are unchanged.

Tests chain the real handlers in create_test.go's style: real board store in a temp file behind a real `api.NewHandler` over httptest, ui pointed at it — needed to prove the refusal strings ("title is required", the 500-character sentence, "no such card") flow through verbatim. Arms: page wiring on all three columns including Done; middle-card edit keeps neighbors' order in the fragment and the store; a Done-column card's edit keeps `card--done` and its column; blank and over-long rejections state their reason at the card with the original title and unchanged List probes; cancel is proven request-free markup-and-script-wise; the stale 404 states the banner over the truth without the card.
