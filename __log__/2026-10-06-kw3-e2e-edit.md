The KW3 wave-end contract: the edit feature's parent scenarios re-executed
in real chromium — no new Gherkin, suite extension only, no product-code
changes.

**Landed:** `e2e/kw3-edit.js` — a third lane script mirroring the KW1/KW2
conventions exactly (self-contained: builds its own binaries, seeds temp
dbs through the board seed tool, free port, `/board` readiness probe,
SIGTERM teardown, per-scenario OK lines, fresh server per scenario). The
kw1/kw2 lane files are untouched; the Makefile `e2e` target gained the
third lane and `e2e/README.md` gained the KW3 section.

Scenario 1 ("Edit card text keeps place") seeds across all three columns,
edits a middle To Do card through the card's Edit control, and asserts the
whole-board DOM structure is identical except that one title — same id,
same index between the same neighbors, same done flags — with a `window`
marker proving no reload, the band prefilled with the existing text, and no
done treatment on the To Do card; then edits a Done card and asserts the
updated text keeps its `card--done` treatment (done is column membership,
which a title change never touches); a reload then agrees card-for-card
with a fresh GET /board.

Scenario 2 (edit leg of "Operation on missing card") stages the Given
out-of-band: after the page is loaded, the lane deletes the target card's
row straight from the kanban data file with the `sqlite3` CLI from its own
process (`PRAGMA busy_timeout` guards concurrent locking). No card DELETE
endpoint exists before KW4, so a direct file mutation is the only honest
way to make "no card exists with identifier X" true server-side while the
page stays stale. Saving the edit on that stale card then states "no such
card" in the missing-card banner, the card's node is gone with no phantom
remnant (no node with its id, no form targeting it), the page mirrors
GET /board, the window marker proves the failure arrived by fragment swap,
and neither the banner nor the divergence survives a reload.

Scenario 3 covers ui/06's stated rejections on the edit surface: a
whitespace-only title states "title is required" at the editing card with
DOM and GET /board untouched and the original titles intact after reload;
501 characters state the character limit at the card, likewise leaving the
board unchanged. The two rejection legs target different cards so their
`p#edit-error-{id}` arms can't shadow each other.
